# JHipster Gap Analysis

## Purpose

This document compares the portal target architecture with common JHipster-generated application capabilities. It is evidence-based: implementation evidence is marked pending where not yet built.

## Comparison summary

| Criterion | Portal target | Typical JHipster baseline | Implementation evidence | Gap / note |
|-----------|---------------|---------------------------|-------------------------|------------|
| Architecture | Spring Boot + Angular modular monolith with explicit module boundaries | Spring Boot + Angular application with generated layers | ADR-0001, modules doc; code pending | Portal needs Modulith/ArchUnit enforcement. |
| Authentication | Same-origin session BFF; no browser JWT storage | Often supports JWT, OAuth2, or session modes depending configuration | ADR-0002 | Portal intentionally avoids JWT in browser storage. |
| CSRF | Mandatory for unsafe browser requests | Depends on auth mode; JWT APIs often disable CSRF | Auth design pending implementation | Must verify Spring Security config. |
| Password hashing | Argon2id target | Commonly BCrypt in many generated apps | Crypto design; dependency present | Encoder implementation pending. |
| RBAC | Database-backed permissions with reserved roles | Role/authority model generated, often role-name centric | ADR-0003, RBAC docs | Portal requires fine-grained permission matrix. |
| Final admin protection | Required invariant | Not generally generated by default | RBAC design | Tests pending. |
| MFA | TOTP and recovery code target | Not always generated by default | Auth/crypto docs | Implementation pending. |
| Audit integrity | Append-only hash chain | Standard audit fields may exist, tamper evidence not default | ADR-0004 | Migrations and verifier pending. |
| Localization | Runtime i18n with default `fa-IR` and RTL | JHipster supports i18n; RTL depends on customization | ADR-0005 | Persian-first UX still pending. |
| Observability | Micrometer, Prometheus, OpenTelemetry | Actuator/Micrometer common; OTel depends on setup | `backend/pom.xml` dependencies | Custom meters/alerts pending. |
| Deployment | nginx same-origin deployment | Generated Docker/K8s options vary | Deployment doc | Compose/nginx config pending. |
| Security docs | Threat model, ASVS checklist, secure coding standard | Usually project-specific add-on | Docs in this repository | Evidence must be kept current. |
| Testing | RBAC matrix, security integration, architecture tests | Generated unit/integration scaffolds | Test plan | Tests pending. |
| Bootstrap admin | One-time env-based first admin | Generated user registration/admin varies | Runbook/design | Implementation pending. |

## Decision criteria

The portal should not be considered "better than JHipster" by assertion. It should be evaluated against:

- Code evidence for security controls.
- Test coverage for privilege boundaries.
- Operational simplicity.
- Upgrade and dependency maintenance burden.
- Documentation accuracy.
- Fit for same-origin enterprise administration workflows.

## Current conclusion

The repository currently contains a targeted architecture and documentation baseline for controls that often require customization beyond a generated application. Most implementation evidence is pending, so the current advantage is **design specificity**, not completed functionality.
